# 评估体系说明

> 本文档面向系统维护者、研究人员和产品决策者，解释「为什么做评估、如何实现、以及每个指标的意义」。

---

## 一、为什么需要评估体系

RAG（Retrieval-Augmented Generation）系统由两个核心环节组成：**检索**和**生成**。任何一个环节出现问题都会导致最终答案质量下降，但两类问题的原因和修复方式完全不同：

| 问题类型 | 表现 | 原因 | 修复方向 |
|----------|------|------|----------|
| 检索失败 | 答案说「找不到相关信息」 | 向量距离不够近、实体未命中 | 改进 Embedding / 图谱扩展策略 |
| 生成幻觉 | 答案听起来正确但内容不在文档中 | LLM 依赖自身先验知识 | 加强提示词约束、忠实度过滤 |
| 策略选择不当 | 不同问题类型需要不同检索路径 | 没有量化对比基准 | A/B 策略测试找最优配置 |

**没有量化评估，优化工作就是盲人摸象。** 每次修改检索策略、更换 Embedding 模型、调整 Top-K，都需要可复现的指标来判断「是变好了还是变坏了」。

## 二、五类评测模块

### 2.1 问答标准集（Dataset Eval）

**是什么：** 上传带有标准答案的问答对（Excel/CSV），系统自动调用检索+生成流程，并用语义相似度对比实际回答与标准答案。

**衡量什么：** 端到端系统质量——从用户提问到最终答案是否正确。

**使用场景：**
- 上线前回归测试
- 比较不同 LLM 模型的答案质量
- 客户验收时的量化演示

**关键指标：**
- `pass_rate`：答案通过率（语义相似度超过阈值的比例）

---

### 2.2 客观题文档（Objective Doc Eval）

**是什么：** 上传含有选择题、判断题的 Word 文档，系统从文档中抽取题目，调用 RAG 作答，自动评分。

**衡量什么：** 系统在结构化知识问答上的准确率，类似于「闭卷考试」。

**使用场景：**
- 工艺规范知识的覆盖度验证
- 新文档入库后的效果回测

---

### 2.3 检索 Harness（Retrieval Harness）

**是什么：** 这是评估体系的核心模块。上传带有「金标准答案块 ID」的标注集（JSONL/CSV），系统只运行检索（不生成答案），逐题计算命中情况。

**衡量什么：** 检索器本身的质量，与生成质量无关。

#### 指标详解

**Hit Rate（命中率）**
```
Hit Rate = 命中题目数 / 总题目数
```
至少有一个金标准 chunk 出现在检索结果 Top-K 中，即视为命中。这是最直观的「检索有没有找到」。

**Recall@K（召回率）**
```
Recall@K = ∩(检索结果, 金标准) / |金标准|
```
衡量金标准中的内容被检索结果覆盖了多少比例。当一个问题对应多个相关段落时，单纯命中率不够，Recall 更全面。

**MRR（Mean Reciprocal Rank，平均倒数排名）**
```
MRR = 1/N × Σ (1 / 第一个命中位置)
```
衡量金标准在结果列表中排名的靠前程度。命中在第1位得1分，第2位得0.5分，依此递减。MRR 高意味着相关结果不只是出现在结果中，而且排在靠前。

**NDCG@K（归一化折损累积增益）**
```
DCG@K = Σ rel(i) / log₂(i+1)
NDCG@K = DCG@K / IDCG@K
```
NDCG 综合考虑了「有没有命中」和「命中的排名质量」。比 MRR 更细腻：
- 多个金标准时，靠前的金标准权重更高
- 归一化到 [0,1] 便于跨任务比较

**为什么三个指标都需要：**
- Hit Rate：快速判断检索有没有覆盖
- MRR：判断相关结果是否在前面（影响用户体验）
- NDCG：综合排序质量的黄金标准，最适合用于策略对比

---

### 2.4 忠实度检测（Faithfulness）

**是什么：** 上传「问题 + 回答 + 参考段落」三元组（JSONL），LLM 逐条审查回答中的每个声明是否能在参考段落中找到依据。

**为什么重要：** RAG 的核心承诺是「答案来自文档」。但 LLM 有时会：
1. 将训练数据中的知识混入回答（知识泄露）
2. 对段落内容进行错误推断（过度演绎）
3. 凭空编造听起来合理的细节（幻觉生成）

这三类问题对航空工艺规范这类高安全需求场景尤为危险。忠实度检测提供了一个自动化的「事实核查层」。

**关键指标：**
- `faithfulness_rate`：忠实答案占比
- `avg_score`：各条答案的平均忠实度分（0~1）
- `unsupported_claims`：每条回答中具体哪些声明缺乏依据（可用于定向改进提示词）

**实现原理：**
```
对每条样本：
  1. 拼接参考段落作为 context
  2. 向 LLM 发送结构化 prompt："判断以下回答的每句话是否有段落依据"
  3. LLM 返回 JSON：{ faithful, score, unsupported_claims, reason }
  4. 汇总统计
```

**局限性：** LLM 本身也可能判断错误，建议将忠实度低的样本人工复核。

---

### 2.5 A/B 策略对比测试

**是什么：** 同一份标注集，同时在多个检索策略下执行，自动输出每个策略的 Hit Rate / MRR / NDCG 并排名，找出最优配置。

**为什么重要：** 本系统支持多种检索策略：
| 策略 | 特点 | 适合场景 |
|------|------|----------|
| `parallel` | 向量+全文+图谱并行，RRF 融合 | 通用问题 |
| `sequential` | 按置信度依次尝试各路 | 有明确实体的问题 |
| `graph_augmented` | 以图谱关系扩展候选段落 | 关系型问题（A 与 B 的关联）|
| `gnn` | 图神经网络语义匹配 | 隐式结构相关问题 |

不同数据集、不同业务领域，最优策略可能不同。A/B 测试的价值在于：
1. **客观比较**：排除主观判断，用数据说话
2. **快速迭代**：新增策略后立即验证效果
3. **领域适配**：为特定业务场景选出最合适的策略

**输出示例（按 NDCG 排名）：**
```
排名  策略              Hit Rate  MRR     NDCG
1     graph_augmented   78.5%     0.6821  0.7234
2     parallel          74.3%     0.6412  0.6891
3     sequential        71.2%     0.6104  0.6523
4     gnn               68.9%     0.5877  0.6201
```

## 三、评估数据的准备

### 检索 Harness 标注集格式（JSONL）

```jsonl
{"question": "铝合金焊接前表面处理的具体要求是什么？", "gold_chunk_ids": ["doc001_chunk_0023"], "gold_doc_ids": ["doc001"], "domain": "焊接工艺", "strategy": ""}
{"question": "热处理炉的温度均匀性要求是多少？", "gold_chunk_ids": ["doc003_chunk_0145", "doc003_chunk_0146"], "gold_doc_ids": ["doc003"], "domain": "热处理"}
```

**字段说明：**
- `question`：用户问题
- `gold_chunk_ids`：能回答该问题的段落 chunk_id（可多个）
- `gold_doc_ids`：相关文档 ID（没有 chunk 级标注时使用）
- `domain`：领域标签（用于分组分析）
- `strategy`：留空则使用任务级默认策略，否则按行覆盖

### 忠实度评测格式（JSONL）

```jsonl
{"question": "铝合金焊接前需要做什么处理？", "answer": "需要用砂纸打磨氧化层，再用丙酮清洁焊缝两侧各25mm区域，然后在4小时内完成焊接。", "passages": ["铝合金焊接前需打磨氧化层并用丙酮清洁焊缝两侧各25mm。", "焊接应在清洁后4小时内进行。"]}
```

## 四、在系统中使用

进入管理后台 → **测试集评测** 页面，选择对应标签页：

1. **问答标准集**：上传 xlsx/csv → 选择策略 → 开始评测
2. **客观题文档**：上传 docx → 开始测试
3. **检索 Harness**：上传 jsonl/csv → 选策略和 Top-K → 开始
4. **忠实度检测**：上传 jsonl → 开始检测
5. **A/B 策略对比**：上传 jsonl/csv → 勾选要比较的策略 → 开始

所有任务异步执行，可实时查看进度，完成后下载 CSV 结果。

## 五、指标解读与决策建议

| 指标 | 好 | 需关注 | 行动 |
|------|----|--------|------|
| Hit Rate | > 80% | < 60% | 调整 Top-K，改进 Embedding |
| MRR | > 0.7 | < 0.5 | 检查重排序（Reranker）配置 |
| NDCG | > 0.75 | < 0.55 | 综合检索策略需优化 |
| Faithfulness Rate | > 90% | < 75% | 收紧系统提示词，引用检查 |

> 评估是持续过程，建议每次更新 Embedding 模型、检索策略或提示词后重新运行完整评测套件，保留历史结果用于趋势分析。
